# 提交格式与方式

## 1. 提交方式

比赛设立 **A 榜阶段** 与 **B 榜阶段** 两个环节：

- **A 榜阶段（开发阶段）**：报名成功后，可通过天池平台下载训练数据和 A 榜测试数据集（开发集），在本地进行模型调试与训练，并在线提交评测结果。A 榜成绩**仅用于模型开发调优，不计入最终成绩**；A 榜测试集答案不公开，不用于 B 榜模型训练。
- **B 榜阶段（最终评测）**：开放 B 榜测试数据集供下载，参赛队伍据此生成预测结果并提交。**各队伍在 B 榜阶段的历史最优成绩作为最终排名与奖项评定的依据。**

**提交说明**

- A 榜每支队伍每日最多提交 **5 次**，B 榜每日 **3 次**。
- 排行榜整点更新，按评测指标从高到低排名。
- 评测失败不扣除提交次数。

## 2. 提交格式

A 榜和 B 榜均要求提交对应测试集预测结果的 **JSONL** 文件，编码 **UTF-8**，格式与训练集结果格式一致，可参考数据集中的 `submit_pred_ex.jsonl`。每行一篇文献：

```json
{
  "pmc_id": "...",
  "pmid": "...",
  "entities": [
    {
      "identifier": "HP:0000519",
      "type": "Phenotype",
      "offset": 206,
      "length": 30,
      "text": "bilateral congenital cataracts",
      "note": null
    }
  ],
  "association": [
    { "patient_id": "P1", "phenotype": ["HP:0011410"] }
  ]
}
```

- `entities`：**全文所有**表型实体预测结果（对应子任务 1）。
- `association`：**特定患者**的表型实体预测结果（对应子任务 2）。

## 3. 格式要点（务必遵守）

- 文件为 UTF-8 JSONL，**每行一篇文献**。
- `pmc_id` 必须与待预测数据一致且**不得重复**。
- 实际提交应**覆盖对应开发集或测试集的全部文献**（不可漏篇、不可多篇）。
- `entities` 的 `offset` / `length` 必须相对**原始完整全文**。
- 否定表型应在 `entities` 中以 `note: "NO"` 显式标注；`association` 中不应混入否定表型。
- 复合表型在 `identifier` 中以**分号**连接多个 HPO ID；`association.phenotype` 中无法映射的原文表型直接保存原文文本（对应金标准 `-1` 情形）。
- `submit_pred_ex.jsonl` 仅用于展示格式，取自训练集，不含开发/测试集答案。

一个真实示例（取自 `submit_pred_ex.jsonl`，含复合表型 `HP:0025474;HP:0000958`）：

```json
{"pmc_id":"12646972","pmid":"40476394","entities":[{"identifier":"HP:0011368","type":"Phenotype","offset":446,"length":23,"text":"abnormal keratinization","note":null}, {"identifier":"HP:0025474;HP:0000958","type":"Phenotype","offset":1086,"length":32,"text":"red, and dry patches and plaques","note":null}],"association":[{"patient_id":"O1","phenotype":["HP:0025474;HP:0000958","HP:0001622"]}]}
```

> 提交前自检清单见 [07-基线与打榜策略](07-基线与打榜策略.md)。
