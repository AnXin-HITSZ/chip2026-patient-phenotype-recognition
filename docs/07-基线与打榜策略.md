## 1. 官方基线系统

| 子任务 | 方法 |
|---|---|
| 子任务 1（全文表型识别） | 用**指定版本 HPO 训练的 PhenoTagger** 做识别 + 标准化 |
| 子任务 2（患者-表型关联） | **Qwen3-8B** 大模型，prompt 识别指定患者的相关提及，结合上下文将患者与已识别表型关联 |

官方基线**未使用训练集优化**，因此存在明显可超越空间。

## 2. 表型概念识别（PCR）代表方法

PCR = **识别（NER / span 检测）+ 标准化（entity linking / normalization）**。不同方法在这两步的耦合方式与 P/R 取向差异很大，直接决定其在 mention-level 与 document-level 两种 F1 下的表现。

### 2.1 PhenoTagger（Luo et al., *Bioinformatics* 2021）— 官方基线

- 出处：Ling Luo, et al. *Bioinformatics* 37(13):1884–1890, 2021。代码：https://github.com/ncbi-nlp/PhenoTagger
- **核心（混合 = 字典 + 弱监督深度学习）**：① 用 HPO 全部概念名与同义词建字典；② 用字典在文献上做**远程/弱监督自动标注**生成无需人工标注的语料；③ 训练 **BioBERT** 把候选短语分类到 HPO 概念；④ 字典结果与深度学习结果融合。
- 优点：**不需要人工标注表型数据**（与本任务「禁止外部人工标注」高度契合）；换 HPO 版本只需重建字典并重训。
- 缺点：仅用概念名文本、**难以消歧同名概念**；逐候选分类**较慢**；不处理否定/缩写，需额外后处理。

### 2.2 PhenoBERT（Feng et al., *IEEE/ACM TCBB* 2022/2023）— 层次化 CNN + BERT

- 代码：https://github.com/EclipseCN/PhenoBERT
- 核心：深度学习模块抽取候选片段 → 两级层次化 CNN（利用 HPO 层次）粗筛候选 → BERT 精排判定，并可在直接识别失败时**回退到祖先概念**。
- 优点：效率/精度平衡好，显式利用层次，祖先回退利于 document-level 召回。缺点：流水线较重；换版本需重训 CNN/重建词表，迁移成本高于 PhenoTagger。

### 2.3 AutoPCR（Tao et al., *Bioinformatics* 2026）— prompt 驱动、免本体训练

- arXiv:2507.19315
- 三阶段：① 规则 + 神经标注混合抽 mention；② **SapBERT** 向量检索召回 HPO 候选；③ **prompt LLM** 做最终归一化。无需针对特定本体训练，**对新版本 HPO / 未见术语泛化好**，与「≤10B + RAG/prompt」赛制最贴合。缺点：不显式处理临床不确定性（possible/rule out 与确诊同等对待，易假阳）；三阶段串行、吞吐受限。

### 2.4 检索/嵌入式实体链接（SapBERT 等）— 归一化子模块

**SapBERT**（Liu et al., NAACL 2021，https://github.com/cambridgeltl/sapbert ）用自对齐预训练让同一概念的不同表述在向量空间聚拢。用法：把 HPO 每个概念的名称与同义词编码入向量索引，对已识别 mention 检索最近邻得 HPO 候选，再阈值/重排定夺。**换版本零重训**（只需用 2026-06-23 版重建索引），对同义/缩写鲁棒（高召回），但同名消歧、复合切分仍需上下游配合。

### 2.5 候选技术栈小结

| 技术路线 | 代表 | 角色 | P/R 取向 | 换版本成本 | 短板 |
|---|---|---|---|---|---|
| 字典匹配 | HPO 词表 / PhenoTagger 字典侧 | 识别+精确归一化 | 高 P / 低 R | 极低 | 未见同义词、复合漏检 |
| 序列标注 NER | BioBERT/PubMedBERT、PhenoBERT/AutoPCR 抽取侧 | 识别 span | R 偏高、边界准 | 需重训/微调 | 需（弱）监督；不处理否定 |
| 检索式归一化 | SapBERT / BioSyn / 句向量 | 归一化 mention→HPO | 高 R（+重排提 P） | 极低 | 同名消歧、需上游 span |
| LLM 抽取/链接 | AutoPCR、prompt LLM | 识别+链接+决策 | 可调 | 低（RAG 注入） | 幻觉、吞吐、需约束到 HP:0000118 |

**推荐组合（先保 P 再提 R）**：字典打底（高精度、对齐 2026-06-23）→ 弱监督 NER 扩召回 → SapBERT 检索做版本无关归一化候选 → ≤10B LLM 重排与最终链接 → 叠加否定检测 + HP:0000118 子树过滤 + 祖先回退。

## 3. 子任务 1 解题思路

### 3.1 两级评测的策略含义

| 指标 | TP 判定 | 优化侧重 |
|---|---|---|
| Mention-level | offset+length **严格相等** 且 HPO ID 正确 | 精准边界 + 精准链接 |
| Document-level | 只看文档内**去重 HPO 集合**是否命中 | 召回与集合覆盖，可上位归并 |

推论：mention 级容不得半字符偏移；doc 级可用**更宽召回 + 同义/上位归并**。可对两级采用不同后处理：mention 级用高阈值严格输出，doc 级降阈值补召回并集合去重。

### 3.2 复杂现象处理

- **缩写/省略**：扫全文找首次定义 `Full Name (ABBR)`，建**文档级局部字典**，后续 ABBR 回填标准词再链接。
- **否定表型（note=NO）**：金标准 NO **不计 FN**（漏掉不罚），但把否定预测成正常表型会**计 FP**。故否定检测**只减 FP、不增召回风险**，应尽量做：否定线索词（no / without / denied / ruled out / absent）+ 依存范围 + LLM 判定，命中则**丢弃或显式输出 note=NO**。
- **复合表型**：一个 span 对多个 HPO，用**分号连接**；评测按分号拆成独立单元，须**输出全部 ID**，漏一个即一个 FN。
- **无 ID 表型（identifier=-1）**：位置对即算对，输出 `-1` 并保证边界精确。

### 3.3 标准化到指定版本的工程细节

基于本仓库 `hp.obo`（`hp/releases/2026-06-23`）解析：全库 20,413 term，**HP:0000118 后代 19,087 个（含自身）**，577 obsolete。据此：① 沿 `is_a` BFS 取 HP:0000118 后代白名单，非该分支 ID 丢弃；② obsolete 用 `replaced_by` 回填，旧编号经 `alt_id` 归并；③ 同义词冲突按 EXACT > NARROW > BROAD + 上下文择优；④ 输出前对 HPO 集合去重供 doc-level。

### 3.4 弱监督与推荐 Pipeline

禁用外部人工标注数据集，但可用 **HPO 本体自造 distant supervision**：把 name/synonym 回标进 PMC 文本生成银标，训练 NER 与链接器；再用官方 80 篇训练集做少量精调与阈值校准。

| 步骤 | 操作 | 失败模式 |
|---|---|---|
| 1 预处理 | 按 passage offset 拼全局坐标、建缩写字典 | offset 累加错 → 全表错位 |
| 2 候选生成 | 词典 AC + NER + LLM 三路并集 | 词典漏形态；NER 断句错 |
| 3 归一化 | SapBERT 检索 + LLM 校验回填 | LLM 幻觉 ID；近义误链 |
| 4 版本对齐 | HP:0000118 过滤 + replaced_by/alt_id | 输出非该分支或过时 ID |
| 5 否定/复合 | 否定判定输出 NO；复合补全多 ID | 否定漏判→FP；复合漏 ID→FN |
| 6 后处理输出 | offset 校验、去重、双阈值 | 边界不逐字符相等→全部判错 |

## 4. 子任务 2 解题思路

### 4.1 评测定义与空集边界

评价对象是「患者-表型对」：正确归属计 TP，误挂计 FP，漏挂计 FN。Micro-F1 全局累加（被表型多的大患者主导）；Macro-F1 按患者等权平均，**双空（真实与预测均空）时该患者 P=R=F1=1**。

空集是**高风险高回报**操作：真实空 ∧ 预测空 → 满分 1（家系中「未受累」成员判对可白拿分）；真实空 ∧ 预测非空 → F1=0 且额外贡献 micro FP（双输）；真实非空 ∧ 预测空 → F1=0。Macro 对「患者多、每人表型少」极敏感——训练集每患者中位约 9 个表型，部分患者仅 1 个甚至为空；**优先保证表型少的患者不漏那 1–2 个高置信表型**，边际收益远高于给大患者多召回一个。

### 4.2 多患者归属（胜负手）

训练集超半数文献含多个患者/家系成员（平均约 2.6 人/篇，最多 14 人）。`patient_id` 规则：文中有编号则 `O+原编号`（如 `OII.1`），否则 `P+出现序号`。关键是把子任务 1 抽到的每个表型 mention（带全局 offset）正确挂到目标个体。

### 4.3 关联建模路线

| 路线 | 做法 | 适用 |
|---|---|---|
| (a) 就近/共指 | 患者 mention 与表型 offset 的句/段邻近、指代消解（this patient / the proband / 该男孩） | 单患者、分述清晰 |
| (b) 章节结构 | CASE / RESULTS 常按患者分小节，同小节表型归当前个体 | 分述式病例 |
| (c) LLM 关系判定 | 候选表型 + 患者 mention + 上下文喂 LLM 判「是否属于该患者」（官方基线做法） | 交叉描述、代词密集 |
| (d) 家系/表格解析 | Table 常按个体列表型 | 家系表、汇总表 |

### 4.4 推荐 Pipeline 与依赖

1. 子任务 1 产出高质量实体（含 offset、否定 note=NO），**去否定**后作为候选池；
2. 患者定位：把每位患者的（部分）mention 用字符串 + 共指扩展到全文所有指称，切出各患者「活动区间」；
3. 候选对生成：对每个正向表型 × 各患者按邻近度/同段/同小节打分粗筛；
4. 归属判定：就近规则 + LLM 二分类，交叉/代词场景交 LLM，家系表走表格解析；
5. 聚合：按 `patient_id` 收集 → **HPO ID 去重**；
6. 空集策略：仅对强信号「未受累/对照」个体谨慎输出空集。

**强依赖子任务 1**：子任务 1 召回是子任务 2 的天花板；但少量关联表型不在实体池中，纯流水线会永久漏这部分，可让子任务 2 对目标患者段落**独立补抽**。`note=NO` 表型不算患者阳性表型，聚合前必须剔除。

## 5. LLM + RAG 参考方案（≤10B、禁用外部人工标注表型数据集）

核心：把「识别」交给生成式 LLM、把「标准化」交给「本体向量检索 + 重排」，两者解耦，既覆盖未见表达，又严格锁定到 v2026-06-23 的 HPO ID。

### 5.1 可选 ≤10B 开源模型

| 模型 | 规模 | 上下文 | 备注 |
|---|---|---|---|
| Qwen3-8B | 8.2B | 32K / 131K(YaRN) | 官方基线子任务 2 即用它；中英混合、结构化输出好 |
| Qwen3-4B-Instruct-2507 | 4B | 262K | 长上下文、整篇少切分 |
| MedGemma-4B | 4B | 128K | 医学继续预训练，单卡可跑 |
| BioMistral-7B / Llama-3.1-8B | 7–8B | 8K–128K | 通用+生物医学备选 |

> 注意 **Baichuan-M1-14B、MedGemma-27B 超 10B，不可用**。选型看：长上下文、稳定结构化输出、中英混合能力。

### 5.2 RAG 归一化（合规关键）

**HPO 本体是「公开知识资源 + 本体」，允许使用；被禁的是「外部人工标注的表型数据集」。** 只要检索库仅由 HPO 官方文件构建即合规。步骤：① 用指定版本 `hp.obo`/`hp.json`；② 过滤到 HP:0000118 子树；③ 把每个 term 的 `name + synonym`（可拼 def）编码入 FAISS，编码器建议 **SapBERT** 或 **BGE-M3**（多语、长文本、dense+sparse 混检）。归一化时对每个 mention 检索 top-k（如 20）候选 → LLM/交叉编码器重排选定唯一 ID；全部低于阈值则判为「非 HP:0000118 表型」丢弃。可参考已发表的 **RAG-HPO**（*Genome Medicine* 2025）两阶段范式。

### 5.3 Prompt / SFT / 后处理

- **分段**：滑窗按段/句切分（重叠 1–2 句防边界截断），段内 offset 换算回全文绝对 offset。
- **结构化 JSON**：强制输出 `[{"mention","start","end","context"}]`，用 vLLM/SGLang 的 guided/JSON schema 约束。
- **few-shot**：可用训练集 80 篇示例做 in-context 演示（属自有数据，不算外部标注）。
- **SFT**：HPO 字典远监督 + 80 篇金标做 **LoRA/QLoRA** 高效微调；归一化仍靠 RAG 保证版本一致。
- **校验**：LLM 给的 ID 必须命中 v2026-06-23 且在 HP:0000118 子树内，否则用检索候选替换或丢弃（杜绝幻觉/过期 ID）；用 `str.find` 校正 span 的 start/end。

```
检索库构建  hp.obo(v2026-06-23) → 过滤 HP:0000118 → name/synonym/def → SapBERT/BGE-M3 → FAISS
分段抽取    全文滑窗 → LLM(Qwen3-8B) → JSON{mention,offset,否定/复合标记}
候选归一化  mention → 向量检索 top-k → LLM/交叉编码器重排 → HPO ID(+阈值门控)
患者关联    LLM 识别患者提及 → 上下文把 mention/HPO 归属到目标患者
后处理校验  词表回填校验 ID → offset 对齐 → 去重合并 → 双子任务输出
```

## 6. 评测口径带例演示

**子任务 1 单篇例子。** 金标准：`A(HP:1@b1)`、`B(HP:2@b2, note=NO)`、复合 `C(HP:3;HP:4 @b3)`；预测：`HP:1@b1`（对）、`HP:2@b2`（把否定当阳性 note=null）、`HP:3@b3`（漏 HP:4）。

- Mention 级：复合拆成 `HP:3@b3`、`HP:4@b3`。TP={HP:1, HP:3}=2；FP={把 B 当普通表型}=1；FN={HP:4}=1（否定实体 B 漏掉不计 FN）。→ **F1_men ≈ 0.667**。
- Document 级：G_d={HP:1,HP:3,HP:4}、P_d={HP:1,HP:2,HP:3}。TP=2, FP=1(HP:2), FN=1(HP:4) → **F1_doc ≈ 0.667**。

**子任务 2 两患者例子。** P1：y={1,3,4}, ŷ={1,3} → F1=0.8；P2：y={5}, ŷ={5,6} → F1≈0.667。
Micro：ΣTP3,ΣFP1,ΣFN1 → **F1_micro=0.75**；Macro：(0.8+0.667)/2 ≈ **0.733**。
若配 F1_men=F1_doc=0.667，则 **Score = 0.25(0.667+0.667)+0.25(0.75+0.733) ≈ 0.704**。

## 7. 数据集实测注意点（本仓库 train 集）

以下为对 `PatientPheX-train.jsonl` 的实测发现，官方文档未全部说明，处理时建议向组织方确认：

- **`note` 字段除 `null`/`NO` 外，训练集另有 3 例 `"D"`**（语义未定义）。建议按「非 NO」保守处理并向组织方确认。
- **少量 `identifier` 非标准 HPO 格式**（共 8 例）：如 `HP:000328`（6 位数字，规范应 7 位）、`MESH:D009069` 等 MeSH 编码、以及个别 `N`。评测按 `HP:` 前缀 + 分号拆分处理，建议对这类异常值单独兜底。
- **约 26 个金标准实体 ID 落在 HP:0000118 分支之外**（如 `HP:0002686 Pregnancy history`、`HP:0003819 Death in childhood`、`HP:0012824 Severity`、`HP:0025237`（obsolete）等），说明标注中存在跨分支/过时 ID。你的分支白名单过滤要考虑这类边界。
- **`association.phenotype` 中 `-1` 项保存原文文本**（共 43 例，如 `"dysmorphic traits"`、`"low-set"`），并非 HPO ID，聚合与匹配时按原文字符串处理。
- **offset 校验 100% 通过**：`scripts/inspect_data.py --check-offset` 对 train 全集 6027 个实体、全部患者 mention 均逐字符对齐，可放心用全局 offset 重建与还原。

## 8. 提交前自检 Checklist

- [ ] 文件为 UTF-8、JSONL、**每行一个合法 JSON 对象**；无 BOM、不要整文件包成数组。
- [ ] 行数 == 测试集文献数（A=20 / B=100），`pmc_id` 集合与测试集**完全一致且无重复**。
- [ ] 每篇含 `pmc_id`、`pmid`、`entities`、`association` 四字段（对齐官方 `submit_pred_ex.jsonl`）。
- [ ] `entities` 每项字段齐全；`type="Phenotype"`；`note` 仅取 `null` 或 `"NO"`。
- [ ] 所有 `offset/length` 用**原始全文全局字符坐标**；能用重建全局文本逐条断言还原出 `entities.text`。
- [ ] HPO ID 全部来自 **2026-06-23 版、HP:0000118 子树**；无废弃/替换 ID；无重复分号、无多余空格。
- [ ] 复合表型以 `;` 连接且各段均为合法 ID；`-1` 实体保留正确位置。
- [ ] `association.patient_id` 全部能在该文 `patient[]` 中找到；未凭空新增患者。
- [ ] `association.phenotype` 为 HPO ID 或（对 `-1`）原文文本；**不含否定表型**；同一患者内建议去重。
- [ ] 先用训练集跑自研评测脚本复现四个 F1，与手算小例子对齐后再提交；善用「评测失败不扣次数」先验证格式。
